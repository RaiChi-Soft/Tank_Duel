# Software Design Document: 3D Tank Trouble (Lightweight)

## 1. Introduction & Project Scope

This document outlines the architecture and design for a lightweight, browser-based 3D tank combat game inspired by *Tank Trouble*.

- **Target Platform:** Web Browsers (Desktop/Mobile/Embedded) via WebGL.
- **Core Tech Stack:** Three.js (Rendering), Cannon-es or Custom Raycasting (Physics), Vanilla TypeScript/JavaScript.
- **Localization:** Game client UI/UX will be fully rendered in **Simplified Chinese (简体中文)**, while the underlying architecture remains generic.

## 2. Architectural Overview

To ensure scalability for local multiplayer (LAN) and AI decoupling, the project adopts a **Component-Based Controller Architecture** coupled with an **Event-Driven Lifecycle**.

- **Decoupling Input from Entity:** Tanks do not listen to keyboard/mouse events directly. Instead, they expose a standard API (`drive()`, `rotateTurret()`, `fire()`). Controllers (Player, AI, or Network) capture input and drive the entity.
- **Data-Driven View:** Three.js meshes strictly mirror the underlying mathematical and physical states.

## 3. System Modules & Class Structure

### 3.1 Game Core & Lifecycle Manager (`GameManager`)

Manages the global state machine of the game: `MENU` $\rightarrow$ `GENERATING_MAP` $\rightarrow$ `GAMEPLAY` $\rightarrow$ `ROUND_OVER`.

- Handles the game loop using `requestAnimationFrame`.
- Dispatches global events (e.g., player death, round reset).

### 3.2 Procedural Maze Generator (`MazeGenerator`)

Generates a random 2D grid layout using a **Depth-First Search (DFS) Randomized Algorithm**.

- **Data Representation:** A 2D array where `0` represents open paths and `1` represents walls.
- **3D Translation:** Translates the 2D array into a 3D environment. To keep rendering lightweight, all wall segments share a single `BoxGeometry` and `MeshStandardMaterial` utilizing **`THREE.InstancedMesh`** to reduce Draw Calls to exactly **1**.

### 3.3 Vehicle Dynamics & Turret Controls (`TankEntity`)

The Tank is modeled as a compound object with hierarchical transformations:

- `TankBody (Root)` $\rightarrow$ Handles linear translation ($v$) and chassis rotation ($\theta$).
- `Turret (Child)` $\rightarrow$ Handles horizontal rotation ($\phi$) relative to the chassis.
- `Barrel (Grandchild)` $\rightarrow$ Handles vertical pitch ($\psi$) for elevated aiming.

```
[TankBody Mesh]
   └── [Turret Mesh] (Y-Axis Rotation)
          └── [Barrel Mesh] (X-Axis Pitch)
```

- **Aiming Mechanics (World-to-Screen):** Uses a Three.js `THREE.Raycaster` projecting from the camera through the mouse cursor onto an invisible infinite ground plane to calculate the target point $\vec{P}_{target}$. The turret smoothly interpolates its rotation towards $\vec{P}_{target}$ using standard spherical linear interpolation (Slerp) constraints.

### 3.4 Physics & Ricochet Engine (`PhysicsEngine`)

Since commercial 3D physics engines (like Ammo.js) can be heavy, a **custom lightweight continuous collision detection (CCD)** or a minimized **Cannon-es** implementation is preferred.

- **Projectile Bouncing:** When a shell hits a wall, its new velocity vector $\vec{v}_{new}$ is calculated using the wall's surface normal $\vec{n}$:

  $$\vec{v}_{new} = \vec{v}_{old} - 2(\vec{v}_{old} \cdot \vec{n})\vec{n}$$

- **High Lethality Damage Model:** Tanks possess an explicit `HealthComponent`.

  - `maxHp = 10`
  - `bulletDamage = 100` (Guarantees instakill while preserving structural compatibility for future armor/shield items).

### 3.5 AI Controller Module (`AIController`)

- **Pathfinding:** Implements a lightweight **A\* (A-Star)** algorithm executed directly on the 2D grid matrix generated by the `MazeGenerator`.
- **Line of Sight (LOS):** The AI casts a ray towards the player tank every $N$ frames. If the ray intersects a wall before hitting the player, LOS is blocked. If clear, the AI transitions from `PATROL` to `ATTACK` status, rotating its turret towards the player coordinates and executing `fire()`.

## 4. UI/UX & Localization Design (Chinese Frontend)

While the engine runs on English variables, all user-facing strings are abstracted into a localization configuration.

### 4.2 DOM Overlay UI

To achieve ultra-lightweight UI performance, do not render menus inside Three.js. Use standard **HTML5 / CSS3 overlays** positioned absolutely on top of the WebGL `<canvas>`.

- Use crisp, scalable font stacks optimized for Chinese characters (e.g., `Microsoft YaHei`, `PingFang SC`).

## 5. Network Architecture Foundation (Future LAN Expansion)

To seamlessly implement local network play later without a full architecture rewrite, the current build adheres to the **Client-Server Topography** even in single-player mode.

- **Host-Authority Simulation:** One local client acts as the internal logic server (Host).

- **State Broadcast Serialization:** Tank positions, turret orientations, and spawned projectiles are stripped into minimized JSON buffers or ArrayBuffers:

  `[EntityID, posX, posY, posZ, rotY, turretRotY]`

- This payload is structured to be pushed directly over **WebRTC Data Channels** or **WebSockets** for future peer-to-peer LAN connectivity.

## 6. Development Milestones

1. **Phase 1:** Core loop, DFS 2D Maze generation matrix, and `THREE.InstancedMesh` wall rendering.
2. **Phase 2:** Keyboard/Mouse mechanics for dual-axis tank driving and turret pointing.
3. **Phase 3:** Custom raycast-based elastic shell bouncing and instantaneous health depletion logic.
4. **Phase 4:** Grid-based A* AI pathfinding and threat assessment state machine.
5. **Phase 5:** HTML/CSS Chinese interface overlay integration and asset lightweighting (Low-Poly styling).
